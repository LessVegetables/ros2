# ПР09. Почему метрика обманывала и какие ошибки видны после исправления

Fixture `.course-kit/v1/fixtures/pr09` (v1-w12), `fixture_sha256 = 7fe4b0e5…255e5`
в **обоих** отчётах. Детектор и пороги не менялись (`red-component-baseline-v1`:
R ≥ 180, G ≤ 120, B ≤ 120, площадь ≥ 2 px; IoU-порог сопоставления 0,5).

| | `metrics-before.json` (manifest-leaky, `--allow-leak`) | `metrics.json` (исправленный `data/manifest.json`) |
|---|---|---|
| manifest_sha256 | `4d10c804…7e29` | `3a219eb2…2ba7` |
| split_valid / split_issues | false: 3 нарушения | true: [] |
| test_samples | sample-03, sample-04 | sample-05, sample-06 |
| TP / FP / FN | 2 / 0 / 0 | 1 / 1 / 1 |
| precision / recall / F1 | 1.0 / 1.0 / 1.0 | 0.5 / 0.5 / 0.5 |
| mean_iou (только по TP) | 1.0 | 1.0 |

Без `--allow-leak` evaluator сохраняет отчёт, но завершается с кодом 1:
«Разбиение содержит утечку или нарушает неизменяемый контракт»
(`evaluate-before.txt`). С исправленным разбиением — код 0 (`evaluate-after.txt`).

## 1. Утечка по capture_id (обязательный дефект)

- **Где:** `manifest-leaky.json` кладёт sample-03 (`capture-a`) и sample-04
  (`capture-b`) в test, а sample-01/02 тех же захватов и sample-05/06
  (`capture-c`, `capture-d`) — в calibration.
- **Нарушения:** `capture_id пересекаются между calibration и test`;
  calibration и test не соответствуют контракту групп `split-contract.json`
  (a, b → calibration; c, d → test).
- **Влияние:** test состоял из двух лёгких кадров тех же захватов — TP 2, FP 0,
  FN 0, F1 = 1.0. Детектор ничего не обучал, высокий F1 дал только удачный
  состав test. После исправления (менялись только списки в `data/manifest.json`)
  в test попали трудные кадры: F1 = 0.5. Падение ожидаемо; пороги по test не
  подбирались.
- **Как поймать снова:** запускать evaluator **без** `--allow-leak` (ненулевой
  код при любом пересечении групп), сверять `split_issues == []` и
  `manifest_sha256` в отчёте с хэшем файла в репозитории.

## 2. Пропуск тёмного объекта (FN, sample-05)

- **Где:** sample-05, разметка `cone` bbox [1, 1, 3, 2]; все 6 пикселей объекта
  RGB (160, 20, 20).
- **Почему:** R = 160 < `red_min` 180 — тёмный красный не проходит порог,
  детекций нет вовсе.
- **Влияние:** FN +1 (recall 0.5). При утечке этот кадр сидел в calibration и
  ошибку скрывал.
- **Как поймать снова:** per-sample `predictions` в отчёте — пустой список при
  непустой разметке; отдельная проверка на кадрах с разной яркостью/экспозицией.
  В ROS-тестах для проверки глубины используется заведомо светлый объект
  (sample-01), иначе этот пропуск скрыл бы ошибку 3D.

## 3. Ложная красная компонента (FP, sample-06)

- **Где:** sample-06, область [0, 0, 1, 2] — два пикселя (255, 0, 0) фона;
  настоящий конус [4, 3, 2, 2] найден верно (IoU 1.0).
- **Почему:** baseline знает только цвет и связность. Фон того же цвета и
  площадью ≥ 2 px становится «cone».
- **Влияние:** FP +1 (precision 0.5). Evaluator даже вычисляет для неё
  пространственную точку (−0.4375, −0.1875, 1.0) м: проекция корректна
  геометрически, но это поверхность фона на луче, а не конус. Правильная
  формула не превращает ложную детекцию в настоящий объект — геометрия
  наследует ошибку классификации.
- **Как поймать снова:** `matched: false` с `iou: 0.0` в `predictions`; тест на
  кадре с красным фоном; в будущем — признаки формы/размера и проверка высоты
  над землёй через tf.

## ROS-обёртка (`ros-demo.txt`, `tests.txt`)

Пакет `src/perception_baseline` повторяет тот же алгоритм на байтах
`sensor_msgs/Image` (учитываются `encoding`, `step`, `is_bigendian`).
Для sample-01: bbox [2, 2, 2, 2], u = v = 3, Z = 1000 мм · 0,001 = 1 м,
X = (3 − 3,5)·1/8 = −0,0625 м, Y = (3 − 2,5)·1/8 = 0,0625 м — это же значение
опубликовано в `/perception/objects_3d` (bbox.center и results[].pose) с
stamp RGB и `camera_optical_frame`; `bbox.size = 0`, а диагностика явно
говорит, что размер и ориентация не оценивались.

| Случай | 2D | 3D | `/perception/status` |
|---|---|---|---|
| корректная пара | 1 | 1 точка | OK, `spatial_ok` |
| нулевая глубина | 1 | пусто | WARN, `zero_depth` |
| глубины нет (ожидание 0,3 с) | 1 | пусто | WARN, `missing_depth` |
| разные timestamps | 1 | пусто | WARN, `stamp_mismatch` |
| depth в `camera_link` | 1 | пусто | WARN, `frame_mismatch` |

`colcon test`: 20 тестов (19 passed, 1 skipped copyright), из них 5 ROS-тестов
по топикам (`test_node.py`) — тесты действительно выполнялись, не «0 tests».
